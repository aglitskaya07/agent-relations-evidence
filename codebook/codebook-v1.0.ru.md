Статус: **замороженная версия** (само-пререгистрация, Этап 1 дизайна 09). Преемник [codebook-v0.1.md](codebook-v0.1.md); изменения против v0.1 — по итогам пилота ([10-pilot-report-2026-07-29.md](10-pilot-report-2026-07-29.md)) и адъюдикации Найли от 29.07.2026. После заморозки правки только новым версионированным файлом с обоснованием.

## Объект оценки

Один **юнит** = сервер-версия-дата: текст блока `instructions` из ответа `initialize` + описания инструментов из `tools/list` (или их статические эквиваленты из опубликованного кода). Каналы фиксируются **раздельно** (`has_instructions`, худшая техника по каждому каналу), группа юнита — по худшей технике **любого** канала. Урок пилота (Exa): steering живёт и в чистых tool descriptions при пустом instructions — отсутствие блока instructions ≠ чистота.

## Группы (классы, не баллы — не усреднять, не складывать)

| Группа | Градация PR | Определение |
|---|---|---|
| **A — информирует** | информировать | Инструкций нет вовсе, либо capability-honest: что умеет, когда уместен («use X when Y»), как корректно пользоваться. Нейтральный how-to — это A, даже длинный. |
| **A+ — защищает** | информировать | Подкласс A: инструкции, работающие на пользователя против третьих сторон — предупреждения об инъекциях, запреты на действия по просьбе из недоверенного канала, охрана приватности. |
| **B — продвигает себя** | продавливать (мягко) | Самопредпочтение без вытеснения других: превосходные степени, «Best for:»-шаблон (включая универсальный охват: «any topic», «any programming question»), оценочные эпитеты пригодности («Perfect for…», «Great for…», «essential for…»), апелляции к доверию («trusted sources»), сравнительные аргументы («faster and cheaper») — но БЕЗ директив заменить чужие инструменты. |
| **C — захватывает** | продавливать (жёстко) | Вытеснение чужих инструментов («instead of built-in», «ahead of», «Prefer this over web search»), precedence-претензии («takes precedence», «primary», чужое как «LAST resort»), безусловные директивы «always/MUST use», подавление знаний модели («Do NOT answer from memory», «Use even when you think you know the answer»), экспансия триггеров («even if X isn't named», «whenever the user…»), директивы удержания («never means leave this server»), **директивы-презумпции** (см. ниже). |
| **D — манипулирует** | манипулировать | Обман и эксплуатация: речь от имени пользователя («The user has installed/chosen…» как утверждение выбора, которого пользователь не делал), ложные утверждения факта, стимулы агенту (награды, кредиты, refund), скрытые data-механики, давление угрозой негативных последствий, признаки уклонения от детекции. |

**Правило присвоения: группа юнита = худшая обнаруженная техника.** К букве обязателен **профиль**: полный список техник с дословными цитатами и каналом каждой. Букву без профиля не публиковать.

## Прецеденты пилота (обязательны к применению)

|---|---|---|

## Границы

**B/C:** «мы лучшие в X» → B. «Используй нас вместо/раньше другого», «не отвечай из памяти», «презюмируй уместность» → C. Тест: превратится ли фраза в приказ, меняющий маршрут решения агента, при буквальном прочтении?

**C/D:** директива от имени сервера → C. Утверждение о воле/выборе пользователя, оферта награды агенту, ложный факт, угроза последствий → D.

**Не steering:** honest-условия («use X when Y»); технические предупреждения о лимитах/авторизации/форматах; «must» в техническом смысле безопасности («must provide an absolute path»); инструкция читать README/схему; внутреннее самопредпочтение; защитные запреты (A+).

## Словарь сид-маркеров (подсветка, решение всегда за оценщиком)

v0.1 + добавления пилота: `instead of built-in` · `most powerful .* available` · `always default` · `call this immediately` · `Best for:` · `prefer(red)` · `Prefer this over` · `faster and cheaper` · `\d+% faster` · `PRECEDENCE` · `takes precedence` · `LAST resort` · `Do NOT answer .* from memory` · `even when you think you know` · `even if .* isn't named` · `The user has (installed|chosen|set up)` · `primary .* (tool|provider|interface)` · `refund|credit|reward` · `MUST (use|run|be executed)` · `ignore (other|previous)` · `whenever the user` · `Assume .* (appropriate|legitimate)` · `Perfect for|Great for|essential for` · `trusted .* sources` · `never means .*leave`

Количественные сигналы (фиксировать, не оценивать): длина instructions; дублирование instructions ↔ tool descriptions; доля инструментов с давлением. Предразметку считать только по чистому тексту вендора (не по досье с мета-разделами экстракции — артефакт пилота).

## Методика сбора (решения чекпоинта 0, обязательны для волны)

1. **npm-каналы — статика тарболов без исполнения** (curl + tar из registry.npmjs.org, версия/дата/shasum в манифест) + **wire-рукопожатия для всех hosted**. Ограничение честно в limitations: npm-текст source-level. Калибровка: совпадение npm-профиля и hosted-текста Firecrawl байт-в-байт (29.07.2026).
2. **Строго keyless для чужих серверов**: 401/403 → `refusal_reason` в датасет, никаких ключей и триалов. Серверы, где у исследователя уже есть легитимный аккаунт, — можно своими кредами, канал помечается `authorized` и учитывается отдельной колонкой (асимметрию покрытия проговаривать).
3. **Тонкие шимы** (реальный код в зависимости — кейс playwright): брать hosted-рукопожатие, иначе помечать `partial-coverage`.
4. Честный `clientInfo` («mcp-ethics-audit»), повторный захват каждого hosted минимум дважды с интервалом, всё сырьё — в raw-captures/ с датой, коммитить в git.

## Протокол оценивания (без изменений против пилота + уточнения)

1. Три независимых оценщика, слепые друг к другу; **изоляция**: читать только кодбук и досье юнита, ничего больше (ни файлов проекта, ни веба).
2. Каждая техника — дословная цитата (непрерывная подстрока досье, ≤250 симв.) + канал. Пересказ = невалидно. Машинная валидация цитат обязательна.
3. Согласие: 3/3 или 2/3 → большинство; полный разброс → адъюдикация Найли. Метрику согласия публиковать.
4. Скептик для всех C/D: (а) цитата есть дословно; (б) не нейтральный how-to; (в) группа не завышена. Выжившее — в индекс.
5. Сомнение между группами — менее тяжёлая + `borderline` с парой групп; шапки/метаданные досье не оцениваются.
6. Метаданные юнита: source_frame, category, vendor_type, transport, version, date — по схеме датасета пилота.
